# Структура папок: что где лежит

Проект разложен «по полочкам»: у каждой папки одна понятная задача.

```
димаш/
├── START.cmd           ← запуск всего проекта
├── backend/            ← СЕРВЕР (Python)
├── frontend/           ← САЙТ (то, что видно в браузере)
├── docs/               ← ДОКУМЕНТАЦИЯ (вы здесь)
├── deploy/             ← настройки для размещения в интернете
├── scripts/            ← готовые команды: установить, запустить, проверить
├── Dockerfile          ← рецепт «упаковки» сайта в контейнер
├── docker-compose.yml  ← запуск контейнера одной командой (база SQLite)
├── docker-compose.postgres.yml ← то же, но с базой PostgreSQL (для продакшена)
├── render.yaml         ← настройки для хостинга Render (сайт + PostgreSQL)
├── assets-src/         ← исходники картинок (не публикуются)
├── .gitignore          ← какие файлы не загружать в GitHub
└── README.md           ← краткое описание проекта
```

## backend/ — сервер

```
backend/
├── start.cmd              ← запуск только API
├── setup.cmd              ← установка зависимостей для тестов
├── app/                    ← код сервера
│   ├── main.py             ← ТОЧКА ВХОДА: здесь сервер «собирается» и запускается
│   ├── manage.py           ← СЛУЖЕБНЫЕ КОМАНДЫ: подготовить базу, создать админа, резервная копия
│   ├── core/               ← основа
│   │   ├── config.py       ← настройки (имя сайта, пароль админа, где лежит база)
│   │   ├── database.py     ← подключение к базе данных
│   │   ├── security.py     ← шифрование паролей, создание токенов
│   │   └── rate_limit.py   ← защита от подбора пароля (ограничение попыток входа)
│   ├── models/             ← ТАБЛИЦЫ базы данных (описание полей)
│   │   ├── user.py         ← пользователи, токены, избранное, подписчики
│   │   ├── catalog.py      ← города, барбершопы, услуги, мастера, отзывы
│   │   ├── booking.py      ← записи
│   │   └── shop.py         ← категории, товары, заказы
│   ├── schemas/            ← ПРАВИЛА ПРОВЕРКИ входящих данных (формат телефона, длина имени…)
│   ├── services/           ← БИЗНЕС-ЛОГИКА (самое «умное»)
│   │   ├── booking_service.py  ← расчёт свободного времени, защита от двойной записи
│   │   ├── order_service.py    ← оформление заказа, расчёт доставки
│   │   └── serializers.py      ← превращение данных из базы в ответ для браузера
│   ├── api/                ← АДРЕСА API
│   │   ├── deps.py         ← «кто сделал запрос» (по токену), проверка прав админа
│   │   └── routers/        ← адреса по разделам: auth, catalog, bookings, shop, admin
│   └── seed/               ← ДЕМО-ДАННЫЕ, которыми база заполняется при первом запуске
│       ├── data.py         ← сами данные (барбершопы, мастера, товары)
│       └── seed.py         ← код, который их записывает в базу
├── tests/                  ← АВТОТЕСТЫ API, серверов и бизнес-сценариев
├── data/                   ← файл базы данных barber.db (создаётся сам)
├── .venv/                  ← виртуальное окружение (установленные библиотеки)
├── requirements.txt        ← список библиотек для работы
├── requirements-dev.txt    ← + библиотеки для тестов
├── .env                    ← ваши настройки (не загружается в интернет)
└── .env.example            ← пример настроек
```

Почему так разделено (это называется **слоистая архитектура**):

- **api** только принимает запрос и отдаёт ответ — как официант;
- **services** принимает решения — как повар;
- **models** знает, как хранить данные — как кладовщик;
- **schemas** проверяет, что прислали правильные данные — как контролёр на входе.

Если завтра понадобится мобильное приложение, оно будет обращаться к тем же адресам API —
переписывать логику не придётся.

## frontend/ — сайт

```
frontend/
├── index.html              ← главная страница
├── 404.html                ← «страница не найдена»
├── site.webmanifest        ← описание сайта для установки на телефон (иконка, цвета)
├── pages/                  ← остальные 12 страниц (барбершопы, запись, магазин, кабинет…)
└── assets/                 ← всё, что подключают страницы
    ├── css/                ← ОФОРМЛЕНИЕ
    │   ├── main.css        ← главный файл: подключает все остальные по порядку
    │   ├── base.css        ← цвета, шрифты, базовые правила
    │   ├── ambient.css     ← «живой» фон
    │   ├── components.css  ← кнопки, поля, карточки, иконки
    │   ├── layout.css      ← шапка и подвал
    │   ├── pages/          ← стили отдельных страниц
    │   ├── layers.css      ← многослойные главные картинки
    │   ├── motion.css      ← анимации
    │   └── responsive.css  ← адаптация под планшет и телефон
    ├── js/                 ← ПОВЕДЕНИЕ
    │   ├── core/           ← основа: связь с сервером (api.js), вход (auth.js), корзина (cart.js), переходы (nav.js), утилиты
    │   ├── components/     ← общие детали: шапка/подвал, карточки, логотип, иконки, анимации, выбор времени
    │   └── pages/          ← скрипт для каждой страницы (home.js, booking.js, shop.js…)
    └── img/                ← КАРТИНКИ
        ├── brand/          ← логотипы
        ├── icons/          ← иконки (по одной + общий файл sprite.svg)
        ├── layers/         ← слои главных экранов (фон + фигуры с прозрачностью)
        ├── shops/ masters/ works/ services/ products/ about/  ← фото
        └── favicon.svg     ← значок во вкладке браузера
```

## Остальные папки

| Папка | Что внутри |
|---|---|
| `scripts/` | `setup.ps1` / `setup.sh` — установка; `run.ps1` / `run.sh` — запуск; `test.ps1` / `test.sh` — тесты; `build_icons.py` — сборка иконок в один файл |
| `deploy/` | `vps/install.sh` — установка на сервер одной командой; `vps/update.sh` — обновление; `vps/backup.sh` — резервные копии; `nginx/barber.conf` — веб-сервер nginx; `systemd/barber.service` — автозапуск; `.env.production.example` — пример настроек для сервера |
| `assets-src/` | Оригиналы картинок-слоёв до чистки краёв. Сайт их не использует, они на случай повторной обработки |
| `docs/` | Эта документация + промты для фото |
| `_old_react_scaffold/` | Старая заготовка, с которой начинался заказ. В проекте не используется, оставлена на всякий случай |
