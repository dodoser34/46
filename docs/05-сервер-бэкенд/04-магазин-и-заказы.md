# Магазин и заказы

Файлы: `backend/app/api/routers/shop.py`, `backend/app/services/order_service.py`

## Корзина

Корзина живёт **в браузере** (`frontend/assets/js/core/cart.js`) и хранит только номера товаров
и количество: `[{ id: 3, qty: 2 }]`. Цены в корзине **не хранятся** — их всегда даёт сервер.

Зачем так: пока товар лежит в корзине, цена могла измениться. И главное — злоумышленник
может поменять цену в своём браузере. Поэтому браузеру в этом вопросе не доверяют.

## Оформление заказа — что делает сервер

1. Проверяет имя, телефон, способ доставки. Для курьера адрес обязателен.
2. Объединяет одинаковые товары (если один товар пришёл двумя строками).
3. Для каждого товара:
   - находит его в базе (нет — ошибка 404);
   - проверяет **остаток на складе** (не хватает — ошибка 409 «в наличии только N шт.»);
   - **атомарно уменьшает остаток**, только если его достаточно, чтобы два заказа не купили одну последнюю единицу;
   - берёт **цену из базы** и запоминает её в заказе.
4. Считает доставку:
   - самовывоз — 0 ₸;
   - курьер — **1 500 ₸**, но **бесплатно**, если товаров на **30 000 ₸** и больше.
5. Сохраняет заказ и возвращает его номер и итоговую сумму.

## Статусы заказа

| Статус | На сайте |
|---|---|
| `new` | Новый |
| `processing` | В работе |
| `done` | Выполнен |
| `cancelled` | Отменён |

Статус меняет администратор в панели. Клиент видит заказы в личном кабинете (если оформлял, войдя в аккаунт).

При отмене остатки возвращаются на склад ровно один раз. При восстановлении отменённого заказа товары резервируются заново; если их не хватает, операция откатывается с ответом 409. Заказ и его остатки изменяются в одной транзакции.

Сводка «Выполненные заказы, ₸» суммирует только заказы со статусом `done`, включая их доставку. Это сумма выполненных заказов в системе, а не банковский отчёт о фактически проведённых платежах.

## Оплата

В проекте — **оплата при получении**. Онлайн-оплата картой — следующий этап развития:
для неё нужен договор с платёжной системой (Kaspi Pay, CloudPayments и т.п.).
Такое подключение потребует отдельного платёжного процесса, проверки уведомлений провайдера и обработки ошибок; в текущем проекте онлайн-оплата не подключена.
