## Пример: оформление заказа

| Шаг | Файл | Что происходит |
|---|---|---|
| 1 | [cart.html](../../frontend/pages/cart.html) | Браузер создаёт страницу и контейнер корзины |
| 2 | [main.css](../../frontend/assets/css/main.css) | Подключаются стили полей, карточек и адаптивной сетки |
| 3 | [pages/cart.js](../../frontend/assets/js/pages/cart.js) | JS читает id товаров из localStorage, загружает карточки и создаёт форму |
| 4 | [core/api.js](../../frontend/assets/js/core/api.js) | Отправляет POST `/api/orders` с JSON и токеном, если пользователь вошёл |
| 5 | [frontend_server.py](../../scripts/dev/frontend_server.py) | Локальный прокси передаёт запрос с порта 5500 на 8000 |
| 6 | [routers/shop.py](../../backend/app/api/routers/shop.py) | FastAPI принимает запрос и получает проверенную схему OrderIn |
| 7 | [order_service.py](../../backend/app/services/order_service.py) | Проверяет адрес, цены и остатки, резервирует товары, считает доставку |
| 8 | [models/shop.py](../../backend/app/models/shop.py) | SQLAlchemy сохраняет заказ и его позиции в транзакции |
| 9 | [serializers.py](../../backend/app/services/serializers.py) | Формирует ответ с номером, суммой и составом заказа |
| 10 | [pages/cart.js](../../frontend/assets/js/pages/cart.js) | После успеха очищает корзину и показывает подтверждение |

Передаваемое тело запроса, учебный пример:

```json
{
  "items": [{"product_id": 1, "qty": 2}],
  "client_name": "Димаш",
  "client_phone": "+7 701 000 00 00",
  "delivery": "pickup",
  "address": "",
  "comment": ""
}
```

В запросе нет доверенной цены. Итог определяется в Python по базе. Наличие товара в интерфейсе — предварительная информация: пока посетитель заполняет форму, товар может купить другой человек. Тогда сервер вернёт 409, а страница покажет сообщение.

## Пример: запись к мастеру

`booking.html` задаёт четыре шага. `booking.js` хранит выбранные услугу, мастера, дату и время. GET `/api/masters/{id}/slots` возвращает слоты с `available`. POST `/api/bookings` повторно проверяет дату, соответствие мастера барбершопу, рабочие часы и занятость, затем сохраняет запись.

Если зарегистрированный клиент вошёл до оформления, запись связана с его аккаунтом. Гостевая запись тоже сохраняется, но сама регистрация после её создания не привязывает её автоматически к новому аккаунту.

## Как дорабатывать функцию

Например, требуется добавить поле в заказ:

1. Решите, хранится ли поле в базе и обязательно ли оно. Существующую базу нельзя считать изменённой только после правки Python-класса.
2. Измените модель в `backend/app/models/` и подготовьте изменение схемы действующей базы, если оно требуется.
3. Добавьте поле и ограничения в `schemas/`.
4. Обработайте его в сервисе, верните через сериализатор и выходную схему.
5. Добавьте поле формы в HTML или JS-шаблон и передайте его через API-клиент.
6. Добавьте проверку правильного и ошибочного случая, запустите тесты.
7. Проверьте поведение в браузере и обновите документацию.

В этой доработке структуры таблиц не менялись: исправлены правила работы с существующими данными.

## Проверка после изменений

Из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/test.ps1
```

Если pytest не установлен, сначала выполните `backend/setup.cmd`. Автотесты используют временную базу, а тесты запуска серверов — свободные локальные порты. Демо-база сайта не должна использоваться как тестовая.

В браузере проверьте главную, фильтр каталога, вход, полную запись и её отмену, добавление товара и заказ, историю в кабинете, изменение статусов в админке. Проверяйте ответ API, а не только появление уведомления. Для воспроизводимых проверок используйте отдельную тестовую базу.

## Что уже реализовано и какие границы у проекта

Работают каталог, мастера, отзывы, избранное, запись, магазин, корзина, личный кабинет, администрирование и запуск двух серверов. Оплата — при получении. Рассылки по email и SMS не отправляются: подписка сохраняет адрес в базе. Реальные платежи, внешняя доставка и публикация на домене требуют отдельных настроенных сервисов и не выдаются за подключённые функции.

## Короткий ответ для защиты

«HTML задаёт содержание страниц, CSS оформляет его и адаптирует под экран. JavaScript обрабатывает действия и обращается к REST API. Python с FastAPI проверяет запросы, выполняет правила записи и заказов и сохраняет изменения через SQLAlchemy в SQLite. Интерфейс помогает пользователю, а окончательные цены, остатки, занятость и права доступа определяет сервер».

## Самопроверка

1. Найдите в HTML кнопку и соответствующий обработчик JavaScript.
2. Найдите CSS-правило её активного состояния.
3. В Network определите метод, URL, JSON и статус запроса.
4. Найдите маршрут Python, схему и сервис этой операции.
5. Объясните, что случится при неверных данных или одновременном запросе другого посетителя.
