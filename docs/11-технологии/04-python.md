## Для чего нужен Python

Python выполняется на сервере. Он принимает HTTP-запросы, проверяет данные, обращается к базе и возвращает ответы. Посетитель получает JSON или статические ресурсы; исходники `backend/app/*.py` браузеру для работы не нужны.

В проекте используется Python 3.11+. Установленные библиотеки перечислены с версиями в [requirements.txt](../../backend/requirements.txt): FastAPI обрабатывает API, Uvicorn запускает ASGI-приложение, SQLAlchemy работает с базой, Pydantic проверяет структуры входящих данных. SQLite поддерживается Python; psycopg нужен для PostgreSQL.

## Основы языка

```python
price = 12000
quantity = 2
client = {"name": "Димаш", "phone": "+7 701 000 00 00"}

def subtotal(price: int, quantity: int) -> int:
    return price * quantity

if quantity > 0:
    total = subtotal(price, quantity)
```

Отступы задают вложенность блоков: в проекте используется четыре пробела. `def` объявляет функцию, `return` возвращает результат. `int`, `str`, `bool`, `list`, `dict` — основные типы. `None` обозначает отсутствие значения. Аннотация `price: int` описывает ожидаемый тип, но обычная функция Python сама по себе не проверяет все переданные значения.

`import` подключает модуль; `from ... import ...` — выбранные имена. `try/except` обрабатывает исключения. `with` управляет временем жизни ресурса, например сессии базы. Классы описывают структуру и поведение объектов; через них в проекте заданы модели таблиц и схемы запросов.

## FastAPI: адрес связывается с функцией

Фрагмент из [routers/shop.py](../../backend/app/api/routers/shop.py):

```python
@router.post("/orders", response_model=schemas.OrderOut, status_code=201)
def create_order(data: schemas.OrderIn, db: Session = Depends(get_db),
                 user: models.User | None = Depends(get_optional_user)):
    return ser.order(order_service.create_order(db, data, user))
```

Префикс этого маршрутизатора — `/api`, поэтому полный путь — POST `/api/orders`. Декоратор `@router.post` связывает запрос с функцией. `data` проверяется по `OrderIn`, `Depends(get_db)` предоставляет сессию базы, `get_optional_user` определяет пользователя, если передан действующий токен. Статус 201 означает создание ресурса.

`response_model` описывает результат. Это помогает документировать API и контролировать структуру ответа. Интерактивная документация работающего приложения доступна на http://localhost:8000/docs.

## Pydantic: проверка входа

Фрагмент схемы заказа из [schemas/shop.py](../../backend/app/schemas/shop.py):

```python
class OrderItemIn(BaseModel):
    product_id: int
    qty: int = Field(ge=1, le=20)
```

`ge=1` означает «не меньше 1», `le=20` — «не больше 20». В заказе также проверяются список товаров, длина имени, телефон и способ доставки. Сумма повторяющихся строк одного товара дополнительно проверяется сервисом. Если входная схема не пройдена, FastAPI обычно отвечает 422.

Проверка формата не заменяет проверку правил: правильный по формату id может не существовать, а товар — закончиться. Эти случаи обрабатывает сервис.

## SQLAlchemy и база данных

`models.Product` описывает таблицу `products`: id, название, цену, остаток и другие поля. Связи `relationship()` позволяют, например, получить позиции через `order.items`.

`Session` — рабочая сессия обращения к базе. `db.get(Model, id)` ищет запись по первичному ключу, `select(Model)` строит запрос, `db.add()` добавляет объект, `db.commit()` фиксирует транзакцию, `db.rollback()` отменяет её незавершённые изменения.

Транзакция объединяет связанные изменения: заказ и уменьшение всех его остатков должны сохраниться вместе. Если один товар отсутствует, нельзя оставить списание других товаров без созданного заказа.

Локально используется `backend/data/barber.db`. База создаётся при запуске, если включён `INIT_DB_ON_STARTUP`. Демонстрационные данные добавляются при `SEED_DEMO_DATA=true`. Изменение `seed/data.py` не является редактором уже заполненной базы: действующие записи сами от этого не перезаписываются.

## Защита от конкурирующих операций

Два покупателя могут одновременно заказать последнюю единицу товара. В [order_service.py](../../backend/app/services/order_service.py) остаток уменьшается условным SQL UPDATE:

```python
reserved = db.execute(update(models.Product).where(
    models.Product.id == product_id, models.Product.stock >= qty,
).values(stock=models.Product.stock - qty).execution_options(synchronize_session=False))
```

Если изменена не одна строка, товар не удалось зарезервировать. Сервер откатывает транзакцию и возвращает конфликт. При отмене заказа товар возвращается на склад один раз; восстановление отменённого заказа требует повторного резервирования.

Для записи [booking_service.py](../../backend/app/services/booking_service.py) сначала блокирует изменения по выбранному мастеру, затем проверяет пересечение интервалов. Услуга на 90 минут в 10:00 занимает и начало слота в 11:00. Уникальный индекс дополнительно запрещает одинаковые начала активных записей. Восстановление отменённой записи тоже проверяет занятость на всю её продолжительность.

## Вход и права

Пароль не сохраняется открытым текстом: [security.py](../../backend/app/core/security.py) создаёт соль и хеш PBKDF2-SHA256. При входе результат повторного вычисления сравнивается с сохранённым значением. Это хеширование, а не обратимое шифрование.

Токен — случайная строка, сохранённая в таблице `auth_tokens`; это не JWT. `get_current_user` требует действующий токен, `get_admin` дополнительно проверяет признак администратора в базе. Срок действия задаётся `TOKEN_TTL_DAYS`.

## Ошибки API

| Статус | Значение в проекте |
|---|---|
| 200 | Операция выполнена / данные получены |
| 201 | Создан пользователь, заказ или запись |
| 400 | Нарушено правило операции: например, отсутствует адрес курьера |
| 401 | Требуется вход или токен недействителен |
| 403 | Пользователь не администратор |
| 404 | Объект не найден |
| 409 | Конфликт: занятое время, недостаточный остаток, повторный email |
| 422 | Неверный формат или ограничения полей |
| 429 | Превышено число попыток входа |

Видимая посетителю ошибка передаётся через `HTTPException(..., detail)`. Непредвиденные исключения нужно искать в терминале сервера; не заменяйте их безусловным «успехом» на странице.

## Окружение и запуск

`.venv` изолирует библиотеки проекта. `.env` содержит локальные настройки и не включается в Git. Переменные процесса имеют приоритет над `.env`. Нельзя публиковать реальные пароли и строки подключения.

Из папки `backend`: `.\start.cmd`. Для установки библиотек тестирования: `.\setup.cmd`. Затем `.\.venv\Scripts\python.exe -m pytest -q`.

Общий launcher в `scripts/dev/launcher.py` следит за изменениями Python-файлов в `backend/app` и перезапускает только API. Процессы на Windows изолированы от сигналов общей консоли, чтобы сохранение файла не выключало фронтенд. Для настройки базы и списка маршрутов смотрите `app/main.py`, для бизнес-правил — соответствующий сервис.

## Вопросы для защиты

**Почему нужен FastAPI?** Он связывает HTTP с функциями Python, использует схемы данных и формирует описание API; правила работы приложения написаны в наших сервисах.

**SQLite — часть фронтенда?** Нет. Доступ к файлу базы имеет сервер, браузер обращается к данным через API.

**Зачем rollback?** Чтобы ошибка в середине операции не оставила частично списанные товары или другие несогласованные изменения.

**Практика.** В `/docs` раскройте GET `/api/products`, выполните запрос и найдите соответствующий маршрут, схему ответа и функцию сериализации в исходниках.
