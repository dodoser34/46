# Инструкция по деплою Blind Barber

Сайт — один сервис: FastAPI отдаёт и API (`/api/...`), и страницы сайта.
Проверка, что всё работает: открыть `https://ваш-адрес/api/health` → `{"status":"ok","database":"ok"}`.

Выберите **один** вариант:

| Вариант | Когда выбирать | Время |
|---|---|---|
| [A. Render](#вариант-a-render-проще-всего) | Нужна ссылка на сайт быстро и бесплатно (для защиты) | ~10 минут |
| [B. VPS одной командой](#вариант-b-свой-сервер-vps-одной-командой) | Есть свой сервер Ubuntu и домен, сайт нужен надолго | ~15 минут |
| [C. Docker](#вариант-c-docker) | На сервере уже стоит Docker | ~10 минут |

## Подготовка (для вариантов A и B через git)

Проект нужно загрузить на GitHub — хостинг берёт код оттуда.

1. Зарегистрируйтесь на github.com и создайте **новый пустой репозиторий** (кнопка New), например `blind-barber`.
2. В папке проекта выполните (подставьте свой адрес репозитория):

```bash
git init
```

```bash
git add .
```

```bash
git commit -m "Blind Barber"
```

```bash
git branch -M main
```

```bash
git remote add origin https://github.com/ВАШ-ЛОГИН/blind-barber.git
```

```bash
git push -u origin main
```

Файлы с паролями (`backend/.env`), база данных и виртуальное окружение в GitHub **не попадут** —
это настроено в `.gitignore`.

## Вариант A. Render (проще всего)

1. Зайдите на **render.com**, войдите через GitHub.
2. Нажмите **New → Blueprint** и выберите репозиторий `blind-barber`.
3. Render прочитает файл `render.yaml` и покажет, что создаст:
   - **barber** — сайт (собирается из `Dockerfile`);
   - **barber-db** — база данных PostgreSQL.
4. Нажмите **Apply**. Сборка займёт 3–7 минут.
5. Откройте сервис **barber** → вверху будет адрес вида `https://barber-xxxx.onrender.com`.
6. Пароль администратора: сервис **barber → Environment → ADMIN_PASSWORD** (Render сгенерировал его сам).
   Вход: `admin@barber.kz` и этот пароль.

Обновление: просто сделайте `git push` — Render сам пересоберёт и перезапустит сайт.

> На бесплатном тарифе Render сайт «засыпает» после 15 минут без посетителей — первое открытие
> после этого занимает ~30–60 секунд. Бесплатная база PostgreSQL работает ограниченный срок
> (смотрите условия Render). Перед защитой откройте сайт заранее, чтобы он «проснулся».

## Вариант B. Свой сервер (VPS) одной командой

Нужно: сервер с **Ubuntu 22.04 или 24.04** (например, PS.kz, Hoster.kz, Timeweb, DigitalOcean)
и, по желанию, домен.

1. **Если есть домен** — в настройках домена создайте запись `A`, указывающую на IP-адрес сервера.
   Подождите 10–30 минут.
2. Подключитесь к серверу (на Windows — программа PowerShell):

```bash
ssh root@IP-АДРЕС-СЕРВЕРА
```

3. Скачайте проект на сервер:

```bash
git clone https://github.com/ВАШ-ЛОГИН/blind-barber.git && cd blind-barber
```

4. Запустите установку. С доменом и HTTPS:

```bash
sudo bash deploy/vps/install.sh barber.kz ваша@почта.kz
```

   Без домена (сайт будет по IP-адресу):

```bash
sudo bash deploy/vps/install.sh
```

Скрипт сам:
- установит Python, nginx и certbot;
- создаст системного пользователя `barber` и скопирует сайт в `/opt/barber`;
- установит библиотеки и создаст настройки `backend/.env` со **случайным паролем администратора**;
- подготовит базу данных с демо-данными;
- включит автозапуск (сайт поднимется сам после перезагрузки сервера);
- настроит nginx и, если указан домен, бесплатный HTTPS;
- включит ежедневную резервную копию базы в 03:30 (хранятся 14 дней).

В конце скрипт напишет адрес сайта и **пароль администратора — сохраните его**.

### Обновление сайта на VPS

```bash
cd blind-barber && git pull && sudo bash deploy/vps/update.sh
```

Перед обновлением автоматически делается резервная копия базы. Настройки и данные не затрагиваются.

### Полезные команды на сервере

| Что сделать | Команда |
|---|---|
| Посмотреть, работает ли сайт | `sudo systemctl status barber` |
| Перезапустить сайт | `sudo systemctl restart barber` |
| Посмотреть логи (ошибки) | `sudo journalctl -u barber -f` |
| Сделать резервную копию сейчас | `sudo barber-backup` |
| Сменить пароль администратора | `cd /opt/barber/backend && sudo -u barber bash -c "set -a; . ./.env; set +a; .venv/bin/python -m app.manage set-password --email admin@barber.kz --password 'НовыйПароль123'"` |

## Вариант C. Docker

### C1. Быстро, с базой SQLite

```bash
cp backend/.env.example backend/.env
```

Откройте `backend/.env`, поменяйте `ADMIN_PASSWORD` и запустите:

```bash
docker compose up -d --build
```

Сайт: `http://IP-сервера:8000`. База хранится в томе `barber-data` и не теряется при пересборке.

### C2. Для продакшена, с PostgreSQL

```bash
cp deploy/.env.production.example .env
```

Откройте `.env` и задайте `ADMIN_PASSWORD` и `POSTGRES_PASSWORD`, затем:

```bash
docker compose -f docker-compose.postgres.yml up -d --build
```

Сайт слушает `127.0.0.1:8000` — снаружи его открывает nginx (конфиг `deploy/nginx/barber.conf`).
Если nginx не нужен, в `docker-compose.postgres.yml` замените `"127.0.0.1:8000:8000"` на `"8000:8000"`.

## Все настройки (переменные окружения)

| Переменная | По умолчанию | Что значит |
|---|---|---|
| `ENV` | `development` | `production` — режим для интернета (запрещает стандартный пароль админа) |
| `DATABASE_URL` | SQLite-файл | Адрес базы. Для PostgreSQL: `postgresql://пользователь:пароль@хост:5432/база` (формат `postgres://` от хостинга тоже подходит) |
| `DATA_DIR` | `backend/data` | Папка для базы SQLite и резервных копий |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | `admin@barber.kz` / `admin123` | Администратор, создаётся вместе с демо-данными |
| `SEED_DEMO_DATA` | `true` | Заполнить пустую базу демо-данными |
| `INIT_DB_ON_STARTUP` | `true` | Создавать таблицы при запуске (в Docker — `false`, там это делает команда `init-db`) |
| `WEB_CONCURRENCY` | `1` | Число процессов сервера в Docker: 1 для SQLite, 2–4 для PostgreSQL |
| `TOKEN_TTL_DAYS` | `30` | Через сколько дней нужно войти заново |
| `LOGIN_MAX_ATTEMPTS` / `LOGIN_WINDOW_MINUTES` | `8` / `15` | Защита от подбора пароля |
| `CORS_ORIGINS` | пусто | Нужно, только если фронтенд будет на другом домене |
| `PORT` | `8000` | Порт сервера (Render задаёт сам) |

## Служебные команды

Выполняются в папке `backend` (на VPS — от пользователя `barber`, см. таблицу выше):

| Команда | Что делает |
|---|---|
| `python -m app.manage check` | Проверить настройки и подключение к базе |
| `python -m app.manage init-db` | Создать таблицы и демо-данные (если база пустая) |
| `python -m app.manage create-admin --email a@b.kz --password "Пароль123"` | Создать администратора (или сделать админом существующего пользователя) |
| `python -m app.manage set-password --email a@b.kz --password "Новый123"` | Сменить пароль, сбросить все входы |
| `python -m app.manage backup` | Резервная копия базы SQLite |

## Если что-то пошло не так

| Признак | Что проверить |
|---|---|
| Сервер не стартует, в логах «ADMIN_PASSWORD не задан» | Задайте свой пароль: в режиме production `admin123` запрещён |
| `/api/health` отвечает `503` | Нет связи с базой: проверьте `DATABASE_URL` и что база запущена |
| HTTPS не включился | Домен должен указывать на IP сервера; повторите `sudo certbot --nginx -d домен` |
| На Render долго открывается | Бесплатный сервис «проснулся» после сна — подождите минуту |
| После обновления виден старый дизайн | В браузере Ctrl + F5 |
