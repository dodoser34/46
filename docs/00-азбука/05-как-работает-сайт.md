# 5. Как вообще работает сайт

## Сравнение с рестораном

Самый простой способ понять устройство любого сайта:

| В ресторане | На сайте | В нашем проекте |
|---|---|---|
| Зал, меню, столики — то, что видит гость | **Фронтенд** (сайт в браузере) | папка `frontend`: HTML, CSS, JavaScript |
| Официант: принимает заказ и приносит блюдо | **API** — набор адресов, через которые сайт общается с сервером | адреса вида `/api/bookings` |
| Кухня: готовит, проверяет, что продукты есть | **Бэкенд** (сервер) | папка `backend`: Python + FastAPI |
| Склад и журнал заказов | **База данных** | файл `backend/data/barber.db` |

Гость не ходит на кухню и не лезет на склад. Он говорит официанту, официант передаёт на кухню,
кухня берёт продукты со склада. Так же и сайт: браузер никогда не трогает базу данных напрямую,
он только просит сервер.

## Основные слова

**Браузер** — программа для просмотра сайтов: Chrome, Edge, Safari, Firefox.

**Клиент** — тот, кто просит. Обычно это браузер.
**Сервер** — тот, кто отвечает. Это программа (и компьютер, на котором она запущена).

**Запрос** — сообщение от клиента к серверу: «дай список барбершопов», «запиши меня на 13:00».
**Ответ** — то, что сервер прислал обратно: данные или сообщение об ошибке.

**URL (адрес)** — строка вида `http://localhost:5500/pages/shop.html`. Состоит из частей:

| Часть | Пример | Что значит |
|---|---|---|
| протокол | `http://` | на каком «языке» общаться |
| хост (домен) | `localhost` | какой компьютер. `localhost` — «этот же компьютер» |
| порт | `:5500` | какая программа на компьютере (номер двери) |
| путь | `/pages/shop.html` | что именно нужно |
| параметры | `?id=1` | уточнения: какой именно барбершоп |

**Порт** — номер «двери» программы. На одном компьютере работает много программ, и порт говорит,
к какой из них стучаться. У нас сайт — порт **5500**, сервер API — порт **8000**.

## HTTP: как они разговаривают

**HTTP** — правила разговора браузера и сервера. Каждый запрос имеет **метод** — глагол:

| Метод | Значит | Пример в проекте |
|---|---|---|
| `GET` | получить | `GET /api/barbershops` — список барбершопов |
| `POST` | создать | `POST /api/bookings` — новая запись |
| `PATCH` | изменить часть | `PATCH /api/auth/me` — поменять имя в профиле; `PATCH /api/admin/orders/5` — админ меняет статус заказа |
| `DELETE` | удалить | В нашем проекте не используется: записи и заказы не удаляются, а получают статус «отменён», чтобы осталась история |

В каждом ответе есть **статус-код** — число, по которому сразу понятно, как всё прошло:

| Код | Значит | Когда у нас бывает |
|---|---|---|
| **200** | Всё хорошо | Список товаров получен |
| **201** | Создано | Запись или заказ созданы |
| **400** | Неправильный запрос | Дата в прошлом |
| **401** | Кто вы? Нужно войти | Открыли «мои записи» без входа |
| **403** | Нельзя | Обычный пользователь лезет в админку |
| **404** | Не найдено | Нет такого барбершопа |
| **409** | Конфликт | Время уже занято, товар закончился |
| **422** | Данные не прошли проверку | Телефон из букв |
| **429** | Слишком часто | Много неудачных попыток входа подряд |
| **500** | Ошибка на сервере | Не должно случаться |

Запомнить просто: **2xx** — успех, **4xx** — ошибся клиент, **5xx** — ошибся сервер.

## JSON: в каком виде ходят данные

**JSON** — текстовый формат для данных. Выглядит как словари и списки из [главы 2](02-переменные-и-типы-данных.md):

```json
{
  "id": 1,
  "name": "The Cut",
  "city": "Алматы",
  "rating": 4.9,
  "is_open": true
}
```

Сервер отвечает таким текстом, а JavaScript на странице превращает его в карточку
барбершопа с фото, рейтингом и кнопкой «Записаться».

## API

**API** — это «меню официанта»: список адресов, по которым сайт может что-то попросить у сервера.
Полный список у нас открывается в браузере по адресу http://localhost:8000/docs
(FastAPI делает эту страницу автоматически). Описание простыми словами —
[адреса API](../05-сервер-бэкенд/02-адреса-api.md).

## База данных

**База данных** — хранилище, похожее на набор таблиц Excel.

- **Таблица** — одна тема: пользователи, барбершопы, записи, товары.
- **Строка** — одна запись: один пользователь, один заказ.
- **Столбец** — одно поле: имя, телефон, цена.
- **Первичный ключ (id)** — уникальный номер строки. Двух строк с одинаковым id не бывает.
- **Связь (внешний ключ)** — ссылка из одной таблицы в другую: в записи хранится не имя мастера,
  а его номер `master_id`, и по нему находится сам мастер.

У нас база **SQLite** — она целиком лежит в одном файле `backend/data/barber.db`
и не требует установки отдельной программы. Для сайта в интернете можно подключить
**PostgreSQL** — более мощную базу; код для этого менять не нужно.

## Что происходит, когда вы открываете страницу

1. Вы вводите адрес `http://localhost:5500` и нажимаете Enter.
2. Браузер просит у программы на порту 5500 файл `index.html` и получает его.
3. В HTML написано: «ещё нужны файлы стилей и скриптов». Браузер скачивает CSS и JS.
4. CSS раскрашивает страницу, JavaScript начинает работать.
5. JavaScript отправляет запрос `GET /api/barbershops?sort=rating`.
6. Сервер на Python достаёт барбершопы из базы и отвечает JSON-ом.
7. JavaScript превращает JSON в карточки и вставляет их на страницу.

Весь этот путь со всеми файлами проекта расписан в [пути одного клика](../03-устройство/03-путь-одного-клика.md).
