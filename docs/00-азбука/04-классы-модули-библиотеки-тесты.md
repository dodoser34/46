# 4. Классы, модули, библиотеки, тесты

## Класс и объект

**Класс** — это чертёж. **Объект** — вещь, сделанная по чертежу.

Чертёж «Пользователь» говорит: у каждого пользователя есть имя, email, телефон, пароль
и отметка «админ или нет». А конкретные пользователи — Аружан, Ерлан, демо-аккаунт — это
объекты, сделанные по этому чертежу.

Из проекта (`backend/app/modules/accounts/models.py`, немного упрощено):

```python
class User(Base):
    __tablename__ = "users"          # в базе данных это таблица users

    id = ...                         # номер пользователя
    name = ...                       # имя
    email = ...                      # почта, уникальная
    phone = ...                      # телефон
    password_hash = ...              # не пароль, а его «отпечаток» (см. главу про безопасность)
    is_admin = ...                   # True — администратор
```

Поля класса называются **атрибутами** (или свойствами). Функции внутри класса — **методами**.

В нашем проекте каждый класс-модель = одна таблица в базе данных, а каждый объект = одна строка
этой таблицы. Так устроены `User`, `Barbershop`, `Master`, `Service`, `Booking`, `Product`, `Order`
и другие. Подробно — [таблицы и связи](../06-база-данных/01-таблицы-и-связи.md).

## Модуль

**Модуль** — один файл с кодом, у которого своя задача. Большую программу не пишут
в одном файле на 10 000 строк: в нём невозможно разобраться. Её режут на модули.

Чтобы воспользоваться кодом из другого файла, его **импортируют** (подключают):

```python
from app.core.security import hash_password
```

«Из файла `app/core/security.py` возьми функцию `hash_password`».

В JavaScript то же самое:

```js
import { api } from '../core/api.js';
```

В проекте модулями называют ещё и целые папки по темам: `accounts` (аккаунты), `catalog`
(барбершопы и мастера), `booking` (запись), `shop` (магазин), `administration` (админка).
Подробнее — [модули](../03-устройство/03-модули.md).

## Библиотека и фреймворк

**Библиотека** — готовый код, который написали другие люди и выложили бесплатно.
Не надо изобретать велосипед: например, сжатие картинок или работу с базой данных
уже кто-то написал и проверил.

**Фреймворк** — большая библиотека, которая задаёт «каркас» всей программы.
Вы пишете только своё, а фреймворк берёт на себя рутину.

Что использовано в проекте:

| Название | Что это | Зачем нам |
|---|---|---|
| **FastAPI** | Фреймворк для сервера на Python | Принимает запросы от сайта, сам проверяет данные, сам делает страницу документации `/docs` |
| **Uvicorn** | Программа-сервер | Запускает FastAPI и «слушает» порт 8000 |
| **SQLAlchemy** | Библиотека для базы данных | Позволяет работать с таблицами как с объектами Python, без ручного SQL |
| **Pydantic** | Библиотека проверки данных | Проверяет, что телефон похож на телефон, а число — это число |
| **pytest** | Программа для тестов | Запускает автотесты |

Фронтенд (сайт) написан **без фреймворков**: на чистом HTML, CSS и JavaScript.
Почему так — в [рассказе о проекте](../../ПРОЕКТ-ПРОСТЫМИ-СЛОВАМИ.md#8-почему-сделано-именно-так).

### Зависимости и requirements.txt

Библиотеки, без которых проект не работает, называются **зависимостями**. Их список лежит
в файле `backend/requirements.txt`. Команда `pip install -r requirements.txt` скачивает их
из интернета. `START.cmd` делает это сам при первом запуске.

### Виртуальное окружение (.venv)

Библиотеки ставятся не «на весь компьютер», а в отдельную папку `backend/.venv` только для
этого проекта. Так разные проекты не мешают друг другу. Эту папку не передают через Git:
на каждом компьютере она создаётся заново ([почему](../02-запуск/04-что-передаётся-через-git.md)).

## Тест

**Тест** — маленькая программа, которая проверяет другую программу.

Человек проверяет сайт руками: зашёл, записался, посмотрел. Это долго, и что-то всегда
забудешь. Автотест делает то же самое за доли секунды и каждый раз одинаково.

Пример идеи теста:

```python
def test_нельзя_записаться_дважды():
    первая = записаться(мастер=1, дата="завтра", время="13:00")
    вторая = записаться(мастер=1, дата="завтра", время="13:00")
    assert первая.код == 201      # первая запись создана
    assert вторая.код == 409      # вторую сервер не пустил: время занято
```

`assert` значит «убедись, что это правда». Если неправда — тест «падает» (красный),
и сразу видно, что что-то сломалось.

В проекте 62 автотеста, все проходят. Лежат в `backend/tests/`. Запуск — одной командой,
подробно в [автотестах](../07-тестирование/01-автотесты.md).
