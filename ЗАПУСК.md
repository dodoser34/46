# Как скачать и запустить Blind Barber на другом компьютере

Инструкция для человека, который получил проект из GitHub или в виде исходников и раньше его не запускал. Основной вариант ниже — **Windows 10/11, 64 бит**.

## 1. Что нужно скачать

| Программа | Обязательно? | Где взять и что выбрать |
|---|---|---|
| **Python 3.11** | Да | Для повторения проверенного окружения — [Python 3.11.9](https://www.python.org/downloads/release/python-3119/), в таблице Files выберите **Windows installer (64-bit)**. Это версия проверенного окружения, а не утверждение, что она самая новая |
| **Браузер** | Да | Подойдёт уже установленный Edge, Chrome или Firefox |
| **Git** | Только для `git clone` и работы с историей | [Git for Windows](https://git-scm.com/downloads/win). При скачивании проекта ZIP-архивом Git не нужен |
| **Visual Studio Code** | Нет, только для чтения и изменения кода | [Официальная загрузка VS Code](https://code.visualstudio.com/download), вариант Windows |

**Node.js, npm, MySQL, PostgreSQL и Docker для этого способа запуска не нужны.** Сервер использует SQLite — локальный файл базы. Библиотеки Python установятся автоматически. При первом запуске нужен доступ в интернет для их скачивания.

Если Python 3.11 уже установлен и команда `py -3.11 --version` работает, переустанавливать его не требуется. При наличии нескольких версий команды проекта сначала выбирают Python 3.11, а уже затем пробуют другой доступный Python.

## 2. Установка Python

1. Откройте страницу Python по ссылке выше.
2. Найдите **Files → Windows installer (64-bit)**. Не выбирайте исходники и embeddable package: это другие варианты поставки.
3. Запустите скачанный установщик.
4. На первом экране включите **Add python.exe to PATH**. Оставьте установку Python Launcher, если этот пункт доступен.
5. Нажмите **Install Now**, дождитесь завершения, закройте установщик.
6. Закройте старые окна терминала и откройте новое: Win → введите `PowerShell` → Enter.
7. Проверьте:

```powershell
py -3.11 --version
```

Ожидается строка `Python 3.11.x`. Если `py` не найден, проверьте `python --version`. Если обе команды не найдены, повторно запустите установщик Python с добавлением в PATH, затем снова откройте терминал.

## 3. Как скачать сам проект

### Вариант А — ZIP, самый простой

1. Откройте ссылку на репозиторий, которую передал автор проекта.
2. На GitHub выберите **Code → Download ZIP**.
3. После скачивания нажмите на архив правой кнопкой → **Извлечь всё**.
4. Откройте извлечённую папку. Найдите уровень, на котором лежат **START.cmd**, **README.md**, папки **backend**, **frontend**, **scripts**.
5. Работайте с извлечённой папкой, а не внутри окна ZIP-архива.

Для примеров ниже считаем, что папка проекта находится по адресу `C:\Projects\BlindBarber`. Путь может быть другим: это только пример.

### Вариант Б — через Git

Сначала установите Git. Затем откройте PowerShell в папке, в которую хотите скачать проект:

```powershell
git --version
git clone ССЫЛКА_НА_РЕПОЗИТОРИЙ BlindBarber
cd BlindBarber
```

Вместо `ССЫЛКА_НА_РЕПОЗИТОРИЙ` вставьте реальный адрес, полученный от автора. Не копируйте этот текст как адрес. Для закрытого репозитория нужен доступ к нему.

## 4. Почему после скачивания нет некоторых файлов

Это ожидаемо: `.gitignore` исключает личные и автоматически создаваемые данные. Файлы для запуска остаются в исходниках.

| Чего нет после скачивания | Почему не передаётся через Git | Как появится |
|---|---|---|
| `backend/.venv/` | Библиотеки и интерпретатор привязаны к компьютеру | Первый запуск создаст окружение и установит `requirements.txt` |
| `backend/.env` | Личные настройки и возможные секреты | Первый запуск скопирует **backend/.env.example** |
| `backend/data/barber.db` | Это рабочие пользователи, записи и заказы автора | Первый запуск создаст новую базу и добавит демо-данные |
| `__pycache__/`, `.pytest_cache/` | Служебные кэши | Python и pytest создадут их при необходимости |
| `tmp/`, `temp/`, логи, резервные копии | Временные результаты и личные данные | Для запуска не нужны |
| `assets-src/` | Оригиналы материалов генерации изображений | Для работы сайта не нужны: готовые файлы находятся в **frontend/assets/img/** |

**Не нужно просить у автора его `.env`, `.venv` или рабочую базу, чтобы просто запустить сайт.** В Git остаются код, зависимости, команды запуска, готовые изображения, документация и безопасные примеры настроек.

Копия проекта получает новые демо-данные. Личные записи и заказы с компьютера автора в ней не появятся: перенос рабочей базы — отдельная операция.

`.gitignore` не скрывает файлы в проводнике и не удаляет их с компьютера автора. Он управляет тем, какие новые файлы Git будет учитывать. Подробнее — [что именно исключено из Git](docs/02-запуск/04-что-передаётся-через-git.md).

## 5. Первый запуск всего проекта

1. Откройте извлечённую папку проекта в проводнике.
2. Дважды нажмите **START.cmd**.
3. Не закрывайте появившееся окно. Первый запуск может занять несколько минут.
4. Автоматически выполнятся: создание `backend/.venv`, установка библиотек, создание `.env` из примера, создание базы, запуск API и сайта.
5. Дождитесь надписи **ГОТОВО**. До этого установка или запуск ещё продолжаются.
6. Откройте в браузере **http://localhost:5500**.

Описание API для разработчика: **http://localhost:8000/docs**.

Для запуска из PowerShell можно открыть папку проекта, нажать на адресную строку проводника, ввести `powershell` и нажать Enter. Затем:

```powershell
.\START.cmd
```

Или сначала перейти в папку командой — замените пример своим путём:

```powershell
cd "C:\Projects\BlindBarber"
.\START.cmd
```

## 6. Отдельно бэкенд и отдельно фронтенд

Откройте **два окна PowerShell**. В обоих перейдите в корень скачанного проекта.

Первый терминал — API, база и логика:

```powershell
cd "C:\Projects\BlindBarber"
.\backend\start.cmd
```

Дождитесь **ГОТОВО**. API можно проверить на http://localhost:8000/docs.

Второй терминал — страницы сайта:

```powershell
cd "C:\Projects\BlindBarber"
.\frontend\start.cmd
```

Откройте http://localhost:5500. Для каталога, входа, записи и заказа нужны оба сервера. При работе только фронтенда страницы доступны, но запросы данных сообщат, что бэкенд недоступен.

Если терминал уже открыт внутри `backend` или `frontend`, команда в этой папке одинаковая: `.\start.cmd`.

**Выберите один вариант:** либо общий START.cmd, либо два отдельных запуска. Если запустить оба варианта одновременно, одни и те же порты окажутся заняты.

## 7. Как остановить и запустить снова

- Остановка: **Ctrl+C** в окне запущенного сервера. Если Windows спросит `Terminate batch job (Y/N)?`, ответьте `Y` и Enter.
- При общем запуске останавливаются оба сервера. При раздельном остановите каждое окно.
- В следующий раз снова откройте `START.cmd`. Повторная ручная установка библиотек не нужна, если окружение сохранилось.
- Не переносите папку `.venv` с другого компьютера. Если папку проекта переместили и старое окружение перестало работать, остановите серверы, удалите только `backend/.venv` и запустите START.cmd заново.

## 8. Как убедиться, что всё работает

1. Главная открывается на http://localhost:5500.
2. В «Барбершопах» видны карточки, выбор города меняет список.
3. Войдите под демо-пользователем: **demo@barber.kz / demo123**.
4. Откройте личный кабинет, создайте тестовую запись и проверьте её в кабинете.
5. Добавьте товар в корзину и оформите заказ. Оплата в проекте — при получении.
6. Для проверки админки войдите отдельно под **admin@barber.kz / admin123** и откройте кабинет → панель администратора.

Это стандартные данные новой локальной демо-базы. В уже используемой базе автор мог поменять пароль: пример `.env` не изменяет пароль существующего пользователя автоматически.

## 9. Если нужно изменить настройки

Обычно ничего менять не требуется. Рабочий файл — `backend/.env`; пример — `backend/.env.example`.

При необходимости его можно подготовить вручную из корня проекта, **если `.env` ещё нет**:

```powershell
Copy-Item .\backend\.env.example .\backend\.env
```

Сохраняйте существующие личные настройки. Не называйте файл `.env.txt`: в проводнике включите отображение расширений файлов. После изменения настроек остановите сервер и запустите его снова.

## 10. Ошибки и решения

| Что произошло | Что сделать |
|---|---|
| Команда `py` или `python` не найдена | Установите Python 3.11 с добавлением в PATH, откройте новое окно PowerShell |
| START.cmd «не найден» | Вы находитесь не в корне проекта. Найдите папку с START.cmd и выполните `cd` в неё |
| Установка библиотек не завершается / ошибка подключения | Для первого запуска нужен интернет и доступ к источнику пакетов pip. Восстановите соединение и повторите START.cmd; при ошибке сохраните её текст |
| pip пытается собирать библиотеки под другую новую версию Python | Установите Python 3.11. Остановите серверы, удалите локальную `backend/.venv`, повторите запуск |
| Порт 8000 или 5500 занят | Остановите прежний экземпляр через Ctrl+C; не запускайте общий и отдельный варианты одновременно |
| «Бэкенд недоступен» | Запустите `backend/start.cmd`, дождитесь готовности; затем обновите страницу |
| На localhost:8000 ответ Not Found | Это адрес отдельного API. Сайт открывается на 5500, Swagger — на 8000/docs |
| После правки видна старая страница | Нажмите Ctrl+F5 |
| `.env`, `.venv` и база отсутствуют в GitHub | Это нормально: они создаются первым запуском, а шаблон настроек остаётся в репозитории |
| Браузер не подключается | Проверьте, что окно сервера не закрыто и вы дождались ГОТОВО; откройте именно http, а не https |

Если порты нужно изменить, из корня проекта запустите всё вместе:

```powershell
.\START.cmd --backend-port 8001 --frontend-port 5501
```

Сайт тогда будет на http://localhost:5501, API — на http://localhost:8001/docs. При раздельном запуске передайте обоим одинаковый `--backend-port`.

## 11. Тесты — по желанию, для разработчика

Для обычной работы сайта этот шаг не нужен. Сначала установите библиотеки тестирования:

```powershell
.\backend\setup.cmd
```

Затем из корня проекта:

```powershell
.\backend\.venv\Scripts\python.exe -m pytest backend/tests -q
```

Тесты используют временную базу. Результаты проверенной версии — в [отчёте](docs/07-тестирование/03-готовность-проекта.md).

## 12. Если у вас Linux или macOS

Установите Python с `venv` и `pip`, извлеките проект, откройте терминал в корне:

```bash
python3 --version
python3 scripts/dev/launcher.py all
```

Для отдельных серверов используйте `backend` и `frontend` вместо `all`, каждый в своём терминале. На системах, где `venv` поставляется отдельным пакетом, сначала установите соответствующий пакет своей ОС. Команды `.cmd` предназначены для Windows.
